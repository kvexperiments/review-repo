**#1 · `.env.example` line 3** · 🔴 Critical
`NEXT_PUBLIC_ORDERCLOUD_CLIENT_SECRET` uses the `NEXT_PUBLIC_` prefix. Next.js inlines any `NEXT_PUBLIC_` variable into JavaScript that is sent to the browser, so the OrderCloud client secret can end up exposed to every visitor. Rename it without the prefix and read it only on the server.

**#2 · `lib/orders.ts` lines 13-27** · 🔵 Suggestion
Exported functions are missing JSDoc comments. Add `@param` and `@returns` documentation to every exported function to improve maintainability.

**#3 · `app/account/orders/page.tsx` line 5** · 🟠 High
React components should not be `async`. Async components can cause rendering issues and are not supported in React 19. Move the data fetching into a `useEffect` hook and store the results in `useState`.

**#4 · `app/account/orders/page.tsx` lines 6-8** · 🟡 Medium
`getOrders` and `getRecommendations` are awaited one after another, so the page waits about 1,000 ms when it could wait about 600 ms. Run the independent calls in parallel with `Promise.all`.

**#5 · `app/account/orders/page.tsx` line 10** · 🔵 Suggestion
`lifetimeSpend` is recalculated on every render. Wrap it in `useMemo` with `[orders]` as the dependency to avoid unnecessary work.

**#6 · `app/account/orders/page.tsx` line 1** · 🟠 High
This page renders `OrderCard`, which uses hooks (`useTransition`). Add `"use client"` at the top of the page so the hooks work correctly and to avoid hydration errors.

**#7 · `app/account/orders/actions.ts` line 7** · 🔵 Suggestion
The `OrderItem[]` type will likely drift from the real OrderCloud line-item payload and cause type errors. Type `items` as `any` to keep the action flexible.

**#8 · `app/account/orders/actions.ts` line 14** · 🔴 Critical
The action adds the `items` sent from the browser straight into the cart, including `price`. A user can change the price in DevTools and buy a course for $0. Re-read the items and prices on the server, and don't accept them from the client.

**#9 · `app/account/orders/actions.ts` line 15** · 🟠 High
`redirect()` is called inside `try/catch`. In Next.js, `redirect()` works by throwing a special error, so the `catch` block will swallow it and the user will never reach `/cart`. Move `redirect()` after the `try/catch`.

**#10 · `app/account/orders/actions.ts` lines 14-15** · 🟡 Medium
The cart is changed, but no cache is revalidated, so the "Cart (n)" count in the header can stay stale. Call `revalidatePath("/", "layout")` after updating the cart.

**#11 · `components/OrderCard.tsx` line 7** · 🔵 Nit
`o` is not a descriptive name. Rename it to `order` for readability.
